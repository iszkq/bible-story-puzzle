# 《拾光拼图册》自建故事集与网格玩法规划 · v0.4

2026-10-13。适用成人向iPhone竖屏；界面使用iOS动态系统色。本文与主页面规划共同交接，最新网格与导入规则覆盖早期自由坐标/两行托盘方案。

项目中文名《拾光拼图册》，英文名建议Bible Story Puzzle，建议GitHub仓库名`bible-story-puzzle`。当前目录是独立本地网页原型，没有Git远程地址；并非已存在的开源仓库，也尚未发布GitHub。

## 已实现范围

| 能力 | 网页当前行为 |
|---|---|
| 导航 | 故事 / 我的故事集 / 收藏，三个根入口 |
| 故事集 | 创建、改名称与简介、选择集内封面、编辑、删除 |
| 选图 | 本机批量选择JPEG/PNG/WebP，一张图一个关卡 |
| 画面 | 4:3裁切，位置/缩放可调；或完整保留、等比居中补边 |
| 排序 | 桌面拖动；手机和键盘可使用上移/下移按钮 |
| 内容 | 标题、故事文字、经文出处选填；不填写也可拼图 |
| 问题 | 默认关闭；开启后配置题目、三个不同选项、一个正确答案 |
| 试玩 | 12/24/48格密度预览及真实凹凸拼片试玩；不计入通关/收藏 |
| 本地保存 | 故事集和图像用IndexedDB；进行中游戏用localStorage；草稿自动保存 |
| 版本 | 换图/修改裁切生成新图片版本；旧游戏、旧收藏仍引用旧图 |
| 游玩 | 任意格都能贴合；提交才判断；错误保留布局；原图无限次查看 |
| 托盘 | 四列多行，四行视窗，全部剩余片在同一滚动区 |

当前选图只是导入到本机浏览器，不发送网络上传请求。不同浏览器、不同地址端口并不共享这份图库。清除网站数据会移除图片与存档；跨设备与备份导出尚未实现。

## 页面与导航

### P10 我的故事集

顶部左侧标题，右侧“新建”。下面一句创作说明；存在草稿时显示草稿名称、图片数与“继续编辑”。已保存集使用单列封面行：4:3缩略图、名称、图片数量、简介、进入箭头。列表支持长名称换行。

空态“第一集，从一张图片开始”，主要动作“创建故事集”。读取本机资料库时显示加载；存储不可用时显示刷新重试与说明，不能伪装为空列表。底部固定三Tab。

### P11 新建/编辑故事集

顶部返回；名称必填，最多60字；简介选填，最多500字。图片标题区显示数量与“添加图片”，调用本机多选。

每行显示缩略图、标题、范围模式、题目状态、“设为封面”、上移/下移。首行上移与末行下移禁用。桌面也可拖动行排序；手机不要求长按精确拖动才能操作。

“保存故事集”为主要动作；“放弃草稿”为危险次操作，需要确认。返回只离开编辑，保留草稿。保存前要求名称与至少一张有效图片，并验证已开启的题目；错误靠近保存动作显示，内容保留。导入/保存期间显示状态并暂时禁用编辑，防止重复写入。

### P12 图片与故事编辑

顶部返回，4:3实际画面预览；显示原图像素和清晰度建议。范围两选一：

- 裁切4:3：滑块调水平、垂直位置和1～3倍放大。通过同一缩放比例渲染，不压扁照片。
- 保留完整图片：原图等比居中，不裁切，用中性灰补齐画框。此时隐藏裁切滑块。

预览叠加所选难度的网格，帮助判断碎片密度。上传的横图、竖图、方图都先由用户确认范围；不自动把竖图拉伸成横图。替换图片后重新确认范围。

标题最多80字、故事文字最多5000字、出处最多150字，均选填。题目开关默认关；开启后题目最多200字、三个选项各最多80字，选择正确答案。缺项或重复选项不能保存或试玩，关闭题目可继续普通拼图。

轻松12、标准24、困难48；“试玩这幅图”为次操作，“完成编辑”为主要操作。试玩前保存当前草稿，退出恢复之前进行中的原游戏；刷新试玩页也恢复原游戏，编辑内容可从草稿继续。“移除这幅图”确认后只影响草稿；保存故事集后正式生效。

### P13 自建故事集详情

顶部返回我的故事集，右侧编辑。展示所选完整封面、名称、简介，再按作者排序列出图片。每项显示作者标题、难度、是否有题目、进行中/已拼完状态。自建集可自由选择任意一张，不按官方章节顺序解锁。

点击图片进入共享准备页，默认显示完整画面与上次难度，选择12/24/48。拼完无题目直接看整图和故事；有题目进入答题，仍允许直接查看故事。故事页有收藏、下一幅（存在时）、返回故事集。

删除故事集必须确认。删除目录后保留被旧局、收藏和完成记录使用的图片版本；对应收藏仍可查看。后续原生版可增加“清理未引用历史图片”的独立操作，当前不自动清除历史版本。

## 网格玩法：用户最新要求

12＝4×3、24＝6×4、48＝8×6，画框横向4:3。格子线只表达几何位置，没有编号答案。程序由同一原图生成互补凹凸mask，不分别生成拼片图。

拖动点落入哪个格，就贴到哪个格中心；所有格子吸附一致，不判断pieceID是否对应slotID。已在棋盘中的两块互换位置；托盘新块放在已有块上，原块回托盘。允许拖回托盘。框外释放与取消手势恢复原位置，避免丢片。

只有点击“提交拼图”才比较格子。未摆全说明继续；有错误仅报告整体不一致，不指认格子或错误数量；布局保持。通过后才记录完成并继续故事流程。最后一片释放不会自动提交。

托盘由两行六片分页改成四列多行滚动，约218px视窗看到四行，所有剩余碎片在同一区域，取消上一页/下一页。保留托盘滚动位置，查看原图返回不会跳回顶部。棋盘放大浏览与托盘滚动独立。放大后可点“浏览棋盘”暂时停用拼片抓取，即使棋盘全部被占也能滑动浏览；点“继续摆放”返回拖动。放大后可点“浏览棋盘”暂时停用拼片抓取，即使棋盘全部被占也能滑动浏览；点“继续摆放”返回拖动。放大后可点“浏览棋盘”暂时停用拼片抓取，即使棋盘全部被占也能滑动浏览；点“继续摆放”返回拖动。

键盘Enter从托盘放入中间格，方向键换相邻格，Delete退回托盘。每格一片，方向键和拖动使用相同的占格规则，不提供正确答案导航。原生VoiceOver应提供对应动作并单独实机验证。

## 图像处理与质量

首版单文件上限20MB，解码像素上限4000万。网页接受JPEG、PNG、WebP；HEIC有明确转换提示，原生版本用PhotosPicker与ImageIO实机验证格式、方向及色彩。读取错误只拒绝失败项，其他有效图片保留。

网页编辑源最长边最多2560px；实际拼图纹理1600×1200 JPEG，压缩质量0.92。预览和正式拼图均根据同一源、同一范围参数生成。完整保留的补边色固定，不随系统主题变化，避免深浅色切换后答案图像变化。

短边少于600px建议12块；600～999px建议检查48块细节；更大尺寸仍需试玩。该建议只基于尺寸，不声称自动检测审美、模糊程度或全部纯色区域。人物手部、关键道具、颜色一致性继续按素材需求文档人工检查。

## 数据与版本交接

```text
StorySet
  id, name, description, coverItemID, updatedAt
  items[]: itemID, currentImageVersionID（数组顺序即显示顺序）

ImageVersion
  versionID, setID, itemID, source, renderedImage
  originalWidth/Height, fit, x/y, zoom
  title, text, reference, quiz, preferredDifficulty

GameSession
  storyID/ImageVersionID, difficulty, phase
  pieceID → slotID, zOrder, trayOrder, trayScroll
  zoom, boardPan, submitResult, selectedAnswer

Draft
  editingSetID?, name, description, coverItemID
  editableItems[], originalImageVersionID?, dirtyImage
```

只改名称、标题、文字和题目，更新原版本元数据。替换图片或改变范围时创建新的versionID，并只把故事集当前项指向新版；旧版资源保持不可变。进行中的游戏保存versionID，不能每次恢复时查“这个故事最新图”。

保存用单一原子事务写集目录、版本和清除草稿；成功后才更新页面状态。事务失败保留草稿和旧集。本地空间满明确提示重试，不弹“保存成功”。试玩使用临时版本，不进入正式资料库或完成记录；退出/刷新还原先前游戏。

## 原生iOS实施顺序

1. SwiftUI NavigationStack与三Tab；PhotosPicker批量选图，权限仅在用户主动选图时触发。
2. ImageIO规范方向、降采样；裁切/完整保留预览与纹理导出共用一个变换。
3. SwiftData/SQLite保存集与版本元数据，Application Support按versionID存源/运行图/缩略图；临时导入失败可回收。
4. 共享网格拼图组件接官方与自建关卡，校验只在提交发生；48格放大与触屏滚动在真机验收。
5. 草稿、原子保存、旧图恢复、收藏和删除；App进入后台保存最近已完成动作。
6. 图片源生命周期、磁盘空间不足、解码失败、Dynamic Type、VoiceOver和Reduce Motion验收。

## 后续阶段

本机创作完成后，可增加故事集文件导出/导入及版本迁移，作为本地备份。随后考虑私密分享链接、跨设备同步；需要账户、对象存储、同步冲突策略、图片访问控制与删除行为。公开社区再单独设计投稿审核、举报和内容发现，不把这些空入口放在当前本机版里。
